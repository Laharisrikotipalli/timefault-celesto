The implementation intentionally exercises a controlled failure near the middle of the workflow to test the recovery path. A step-7 fault is injected and recorded, then the resume policy is applied so the system can continue from the last successful checkpoint without discarding the prior work. This is a reliability-oriented proof of recovery rather than a claim of a benign run.

The observed failure demonstrates that the project records the failure details, keeps the run ledger consistent, and restores the workflow on the selected policy. The evidence includes the failure trace, the policy manifest, and the command log that shows both allowed and blocked commands. A trustworthy recovery path must preserve the artifacts and any partial results that were validated before the fault.

The known limitation is that this environment does not provide a full Celesto cloud execution trace or a five-job concurrency test, so those claims remain explicitly unmade. The implementation therefore documents the actual evidence and the unsupported operations rather than inventing benchmark fidelity. The final state reflects the tested workflow and the associated caveats, rather than a false impression of hidden cloud performance.
